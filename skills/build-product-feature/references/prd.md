# Feature PRD

Define what the feature will and will not do before deciding how to implement it.

Inspect the relevant product context and current behavior. Ask only for missing information that materially affects the feature. Write the PRD with:

- The user need and intended outcome.
- The feature scope and explicit non-goals.
- The concrete product behavior or interaction design, including important states and boundaries.
- Acceptance criteria that express the expected result.

Keep the document in product language. Omit technical implementation choices, unrelated product decisions, and empty sections.
